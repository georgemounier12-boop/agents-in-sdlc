GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、すべてのツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、変更ごとに採用または却下できます。エディターを離れずに、追加のプロンプトを使って会話を調整し、作業を改善したり広げたりできます。

この演習では、次の内容を学びます。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントに指示を送り、ハイ コントラストに加えてライト モードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中に、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードも用意したいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。各ファイル編集は差分と **Keep** / **Undo** ボタンとともにチャット内に表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更が適用されます。
   - **Undo** を選択すると変更が取り消され、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツールの使用許可を求められることがあります (たとえば、ターミナル コマンドの実行)。エージェントは一時停止して **Allow** プロンプトを表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けると、エージェントはこれまでの作業から得たコンテキストを保持します。変更したコンポーネント、スタイルの方針、設定に使ったローカル ストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を引き継ぎ、変更内容を確認しながら、ライト モードの追加を提案します。
3. ハイ コントラスト モードと同じように、新しい編集を 1 つずつレビューし、それぞれ **Keep** または **Undo** を選択します。
4. たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとした場合など、エージェントが望まない方向に進んだら、チャット入力欄の横にある **Stop** ボタンで停止して、明確なフォローアップ プロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を送るほうが、最初からやり直すより速くなります。フォローアップ プロンプトで変更を依頼できます。「CSS を簡潔にし、セレクターを重複させず CSS 変数を使う」、「切り替えを 3 つに増やさず、既存の設定パネルにライト モードを追加する」のように方向を修正したり、「両方の切り替えにキーボード ショートカットも追加する」のように範囲を広げたりできます。

## 作業ファイルをレビューする

変更をコミットする前に、エージェントが編集したファイルを確認しましょう。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストの更新が含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントによるアクセシビリティのパターンが反映されていることを確認します。ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージによる設定の保持などを確認してください。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して調整しました。ファイル編集ごとに内容を確認し、変更を採用または却下し、コンテキストを維持したまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する
- ファイル編集を個別に採用または却下する
- フォローアップ プロンプトで進行中のセッションを調整する

[次のレッスン][next-lesson]では、アクセシビリティ作業をプル リクエストとして公開し、このラボを通じてローカルのカスタム エージェントが行った変更をレビューします。
